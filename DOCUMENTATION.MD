## 1. Обзор проекта

**Article Sorter** — инструмент для автоматизированного сбора, хранения и классификации научных и технических статей по теме извлечения данных из медицинских PDF-документов.

Основные возможности:

- Скрапинг из 4 источников: PubMed Central, DOAJ, Towards Data Science, Habr
- Дедупликация по URL, фильтрация слишком коротких текстов
- Ручная разметка статей как релевантных / нерелевантных
- Два алгоритма классификации на выбор: KNN (SBERT) и Naive Bayes (TF-IDF)
- Сохранение обученных моделей на диск — не нужно переобучать при каждом запуске
- Веб-интерфейс на Streamlit и CLI для автоматизации

## 2. Архитектура

```
article_sorter/
├── app.py              # Streamlit веб-интерфейс
├── pipeline.py         # CLI для запуска скрапинга
├── classifier.py       # Два классификатора: KNN и Naive Bayes
├── config.py           # Настройки: БД, API-ключи, таймауты
├── scrapers/
│   ├── base.py         # Базовый класс скрапера (HTTP, retry, TLS)
│   ├── pubmed.py       # PubMed Central (E-utilities API)
│   ├── doaj.py         # DOAJ API
│   ├── towards_ds.py   # Towards Data Science (Medium RSS)
│   └── habr.py         # Habr (RSS + HTML)
├── db/
│   ├── models.py       # SQLAlchemy ORM: таблицы articles, scraping_log
│   └── repository.py   # Репозиторий: CRUD, фильтрация, статистика
└── classifier_cache/   # Создаётся автоматически
    ├── knn_index.pkl   # Сохранённый индекс KNN
    └── nb_model.pkl    # Сохранённая модель Naive Bayes
```

**Слои системы:**

```
[Источники] → [Scrapers] → [Repository] → [SQLite / PostgreSQL]
                                                    ↓
                              [Разметка: ручная / авто]
                                                    ↓
                              [Classifier: KNN | Naive Bayes]
                                                    ↓
                              [Авто-разметка по порогу]
```

## 3. Установка и запуск

### Зависимости

```bash
pip install -r requirements.txt
pip install nltk pymorphy3        # для Naive Bayes (русская лемматизация)
```

При первом запуске Naive Bayes NLTK автоматически скачает нужные ресурсы: `punkt_tab`, `stopwords`, `wordnet`.

При первом запуске KNN скачается модель SBERT (~120 МБ, кэшируется в `~/.cache/huggingface/`).

### Запуск веб-интерфейса

```bash
streamlit run app.py
```

### Запуск скрапинга через CLI

```bash
python pipeline.py                        # все источники, лимиты по умолчанию
python pipeline.py --source pubmed        # только PubMed
python pipeline.py --source habr --max 20 # Habr, максимум 20 новых статей
python pipeline.py --stats                # статистика без скрапинга
```

## 4. Пайплайн: шаги и алгоритмы

### Шаг 1 — Сбор статей (скрапинг)

**Файл:** `scrapers/`, `pipeline.py`

Каждый скрапер наследует `BaseScraper` и реализует метод `iter_articles()` — генератор объектов `ArticleData`.

**Алгоритм базового класса (`base.py`):**

1. Создаётся `requests.Session` с браузерным `User-Agent`
2. При каждом HTTP-запросе добавляется задержка `delay` секунд (по умолчанию 1.5с)
3. При ответе **429 (Rate Limit)** — читается заголовок `Retry-After`, ожидание и повтор (до 3 попыток)
4. При ответе **503** — экспоненциальная задержка и повтор
5. Для серверов со старым TLS (Habr) — принудительный **TLS 1.2** через `TLSAdapter`
6. HTML разбирается через **BeautifulSoup (lxml)**

**Алгоритмы отдельных скрапе­ров:**

| Источник | Протокол | Алгоритм поиска |
|---|---|---|
| PubMed Central | E-utilities REST API (XML) | ESearch с `usehistory=y` → WebEnv/QueryKey → EFetch батчами по 10 |
| DOAJ | REST API (JSON) | Пагинированный поиск по ключевым словам через `+` |
| Towards Data Science | Medium RSS + HTML | Разбор RSS-ленты → скрапинг полного текста каждой статьи |
| Habr | RSS + HTML | Два прохода: по релевантности и по дате публикации |

**PubMed: два прохода:**

```
Проход 1 (sort=relevance): запросы вида "pdf extraction[tiab] AND medical[tiab]"
Проход 2 (sort=pub+date):  те же запросы — для захвата свежих статей
```

Поиск ограничен полями `[tiab]` (title + abstract) — точнее полнотекстового поиска.

**Дедупликация внутри скрапера:** каждый скрапер ведёт `seen_urls: set[str]` и пропускает уже отданные URL в рамках одного запуска.

---

### Шаг 2 — Сохранение в базу данных

**Файл:** `db/repository.py`

Метод `repo.save(article_data)` выполняет:

1. Проверку минимальной длины текста (`MIN_TEXT_LENGTH = 150` символов)
2. Попытку `INSERT` в таблицу `articles`
3. При нарушении `UniqueConstraint` по `url` → возвращает `("duplicate", False)`, статья пропускается
4. Запись в `scraping_log`: количество загруженных, новых, дублей, ошибок

Каждый запуск источника обрамляется вызовами `start_log()` / `finish_log()` — журнал доступен на вкладке «Журнал запусков».

---

### Шаг 3 — Ручная разметка

**Файл:** `app.py` (вкладки «Скрапинг» и «База данных»)

Пользователь размечает статьи вручную через интерфейс:

- **✅ Релевантна** — статья относится к теме (`is_relevant = True`, `relevance_score = 1.0`, `label_source = "human"`)
- **❌ Нерелевантна** — не относится (`is_relevant = False`, `relevance_score = 0.0`)
- Массовая разметка: выбор нескольких строк в таблице → действие на все сразу

Размеченные статьи становятся обучающей выборкой для классификатора.

**Минимум для обучения:** 2 статьи каждого класса (рекомендуется 10+).

---

### Шаг 4 — Обучение классификатора

**Файл:** `classifier.py`

Пользователь выбирает алгоритм и нажимает «Обучить». Модель обучается на всех размеченных статьях (`is_relevant IS NOT NULL`) и **сохраняется на диск** — при следующем запуске приложения загружается автоматически, повторное обучение не требуется.

Подробнее — в разделе [Алгоритмы классификации](#5-алгоритмы-классификации).

---

### Шаг 5 — Автоматическая классификация

**Файл:** `classifier.py`, `app.py`

Загруженная модель применяется к неразмеченным статьям (`is_relevant IS NULL`) батчами:

1. Для каждой статьи формируется входной текст: `title + abstract` (если abstract ≥ 100 символов) или `title + text[:2000]`
2. Текст векторизуется или предобрабатывается (зависит от алгоритма)
3. Модель возвращает `score` — вероятность релевантности от 0.0 до 1.0
4. Score сохраняется в БД: `knn_score` (для KNN) или `bert_score` (для Naive Bayes), а также в общее поле `relevance_score`

---

### Шаг 6 — Авто-разметка по порогу

**Файл:** `app.py`

После классификации пользователь выставляет порог (по умолчанию 0.5) и применяет авто-разметку:

```
score >= threshold  →  is_relevant = True,  label_source = "knn" / "nb"
score <  threshold  →  is_relevant = False
```

Затрагиваются только статьи, у которых `is_relevant IS NULL`. Статьи с ручной разметкой не перезаписываются.

После авто-разметки новые статьи попадают в обучающую выборку — цикл обучения можно повторить с расширенным набором данных.

## 5. Алгоритмы классификации

### 5.1 KNN на SBERT-эмбеддингах

**Класс:** `Classifier` в `classifier.py`  
**Кэш:** `classifier_cache/knn_index.pkl`

#### Обучение

1. Для каждой размеченной статьи формируется текст: `title + abstract`
2. Тексты прогоняются через модель `paraphrase-multilingual-MiniLM-L12-v2` (384-мерные векторы)
3. Векторы нормализуются (L2-норма → единичная длина) для косинусного сходства
4. Нормализованные векторы и метки сохраняются в файл

**Почему предобработка текста не нужна:** SBERT — трансформер, обученный на миллиардах пар предложений. Он кодирует слова в контексте: "not relevant" и "relevant" дают разные векторы. Лемматизация или удаление стоп-слов только разрушат контекст, которым оперирует модель.

#### Предсказание

1. Текст новой статьи векторизуется той же моделью
2. Вычисляется косинусное сходство со всеми обучающими векторами: `sim = q · V^T`
3. Берутся `k` ближайших соседей (настраивается слайдером, по умолчанию 5)
4. Score = взвешенная доля положительных соседей: `Σ(sim_i · label_i) / Σ(sim_i)`

```
score ∈ [0.0, 1.0]
score → 1.0: большинство ближайших соседей — релевантные статьи
score → 0.0: большинство ближайших соседей — нерелевантные статьи
```

#### Параметры

| Параметр | По умолчанию | Описание |
|---|---|---|
| `n_neighbors (k)` | 5 | Число ближайших соседей. Больше → стабильнее, но медленнее |
| `batch_size` | 200 | Статей за один запуск классификации |

### 5.2 Naive Bayes на TF-IDF

**Класс:** `NaiveBayesClassifier` в `classifier.py`  
**Кэш:** `classifier_cache/nb_model.pkl`

#### Предобработка текста

Выполняется функцией `_preprocess_text()` **и при обучении, и при предсказании**:

```
Исходный текст
      ↓
1. Нижний регистр: "PDF Extraction" → "pdf extraction"
      ↓
2. Удаление пунктуации и цифр: "table (2023)." → "table "
      ↓
3. Токенизация (NLTK word_tokenize): "pdf extraction" → ["pdf", "extraction"]
      ↓
4. Удаление стоп-слов EN + RU: ["the", "of", "и", "в", ...] убираются
      ↓
5. Лемматизация:
   - EN: WordNetLemmatizer (NLTK) — "extracting" → "extract"
   - RU: pymorphy3 MorphAnalyzer   — "извлечения" → "извлечение"
      ↓
Обработанный текст: "pdf extract table medical document"
```

**Зачем здесь нужна предобработка:** TF-IDF строит матрицу «документ × токен», где каждый уникальный токен — отдельная фича. Без лемматизации "extract", "extraction", "extracting", "extracted" — четыре разные фичи. Стоп-слова ("the", "of", "и") дают высокую частоту везде и не несут информации о классе, засоряя модель.

#### Обучение

1. Все размеченные статьи проходят предобработку
2. `TfidfVectorizer` строит матрицу весов: `TF-IDF(t, d) = tf(t,d) × log(N/df(t))`  
   Параметр `sublinear_tf=True` заменяет `tf` на `1 + log(tf)` — сглаживает доминирующие слова
3. `MultinomialNB` оценивает условные вероятности слов для каждого класса: `P(слово | класс)`

#### Предсказание

```
P(релевантно | документ) = P(релевантно) × ∏ P(слово_i | релевантно)
```

Возвращается `predict_proba` — вероятность класса 1 (релевантный), значение от 0.0 до 1.0.

#### Интерпретация: топ слов по классам

После обучения доступна кнопка «Топ слов по классам» — показывает слова с наибольшим логарифмическим правдоподобием для каждого класса. Это позволяет проверить, что модель обучилась на осмысленных признаках:

```
✅ Релевантные:    pdf, extract, table, medical, document, clinical, ...
❌ Нерелевантные:  javascript, python, tutorial, dataset, tensorflow, ...
```

#### Параметры

| Параметр | По умолчанию | Описание |
|---|---|---|
| `max_features` | 10 000 | Размер словаря TF-IDF. Больше → точнее, но медленнее |
| `ngram_range` | (1, 2) | Слова + биграммы: "pdf extraction" как единая фича |
| `alpha` | 1.0 | Лапласово сглаживание в MultinomialNB |

### 5.3 Сравнение алгоритмов

| Критерий | KNN (SBERT) | Naive Bayes (TF-IDF) |
|---|---|---|
| **Понимание семантики** | ✅ Да — синонимы близки в пространстве | ❌ Нет — синонимы разные фичи |
| **Поддержка RU+EN** | ✅ Нативно (multilingual модель) | ✅ Раздельные стоп-слова и лемматизаторы |
| **Предобработка текста** | Не нужна и вредна | Необходима и реально помогает |
| **Скорость обучения** | Медленно (~2–5 мин при 500+ статьях) | Быстро (секунды) |
| **Скорость предсказания** | Медленно (матричное умножение) | Мгновенно |
| **Малая выборка (< 50)** | Хорошо | Хорошо |
| **Интерпретируемость** | Низкая | Высокая (топ слов) |
| **Размер на диске** | ~4–20 МБ (зависит от выборки) | < 1 МБ |
| **Доп. зависимости** | `sentence-transformers` (~120MB модель) | `nltk`, `pymorphy3` |

**Рекомендация:** при малой обучающей выборке (< 100 статей) оба алгоритма дают сопоставимое качество. При росте выборки KNN обычно точнее за счёт семантического понимания. Naive Bayes полезен для быстрой итерации и интерпретации.

## 6. Источники данных

### PubMed Central (`pubmed`)

- **API:** NCBI E-utilities — `esearch.fcgi` + `efetch.fcgi`
- **Формат ответа:** XML (JATS)
- **Задержка:** 0.4с (0.15с с API-ключом)
- **Лимит без ключа:** 3 запроса/сек; с ключом — 10/сек
- **Поля:** title, abstract, full text (body), дата публикации, PMC ID
- **URL статьи:** `https://www.ncbi.nlm.nih.gov/pmc/articles/PMC{id}/`
- **API-ключ:** бесплатно на `https://www.ncbi.nlm.nih.gov/account/`

### DOAJ — Directory of Open Access Journals (`doaj`)

- **API:** `https://doaj.org/api/search/articles/{query}`
- **Формат:** JSON, пагинация через `?page=N&pageSize=100`
- **Задержка:** 2.0с
- **Поля:** title, abstract, URL, язык, год публикации
- **Особенность:** запрос только через `+` между словами, не через пробел

### Towards Data Science (`towards_ds`)

- **Протокол:** Medium RSS → HTML
- **Шаги:** разбор RSS → скрапинг полного текста каждой статьи через HTML
- **Язык:** английский
- **Особенность:** TLS 1.2 fallback (Medium иногда отказывает на TLS 1.3)

### Habr (`habr`)

- **Протокол:** RSS + HTML (`habr.com`)
- **Язык:** русский
- **Два прохода:** по релевантности и по дате публикации
- **Поля:** title, abstract (лид-абзац), полный текст статьи

## 7. База данных

### Таблица `articles`

| Поле | Тип | Описание |
|---|---|---|
| `id` | INTEGER PK | Автоинкремент |
| `source_name` | VARCHAR(64) | `pubmed` / `doaj` / `towards_ds` / `habr` |
| `url` | VARCHAR(2048) UNIQUE | URL статьи — ключ дедупликации |
| `title` | VARCHAR(512) | Заголовок |
| `abstract` | TEXT | Аннотация |
| `text` | TEXT | Полный текст |
| `language` | VARCHAR(8) | `en` / `ru` |
| `published_at` | DATETIME | Дата публикации |
| `scraped_at` | DATETIME | Дата загрузки (UTC) |
| `is_relevant` | BOOLEAN | `True` / `False` / `NULL` (не размечена) |
| `label_source` | VARCHAR(16) | `human` / `knn` / `nb` |
| `relevance_score` | FLOAT | Итоговый score 0.0–1.0 |
| `knn_score` | FLOAT | Score от KNN |
| `bert_score` | FLOAT | Score от Naive Bayes |

**Индексы:** `ix_articles_source` (source_name), `ix_articles_relevant` (is_relevant)

### Таблица `scraping_log`

Каждый запуск источника — одна строка. Поля: `source_name`, `started_at`, `finished_at`, `total_fetched`, `total_new`, `total_skipped`, `total_errors`, `error_details`.

### СУБД

По умолчанию — **SQLite** (`articles.db` рядом с `pipeline.py`). Для переключения на PostgreSQL в `config.py`:

```python
DATABASE_URL = "postgresql+psycopg2://user:password@localhost:5432/articles"
```

```
Опции:
  --source NAME    Источник: pubmed | doaj | towards_ds | habr
                   Без опции — запускаются все источники
  --max N          Максимум новых статей на источник
                   Без опции — значение из конфига источника
  --stats          Вывести статистику БД и выйти

Примеры:
  python pipeline.py
  python pipeline.py --source pubmed --max 100
  python pipeline.py --source habr --max 50
  python pipeline.py --stats

Лимиты по умолчанию:
  pubmed:     60 статей
  doaj:       50 статей
  towards_ds: 60 статей
  habr:       60 статей
```

Лог пишется одновременно в stdout и в файл `pipeline.log`.
